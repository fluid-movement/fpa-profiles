SvelteKit 3 remote functions: after a successful form submission the client calls `refreshAll()`, which refreshes every cached query, unless the server handler refreshed queries explicitly (`form.svelte.js`: `should_refresh = refreshes === null && !response.r`). `saveProfile` in `src/routes/players/[playerId]/data.remote.ts` calls `getEditor(...).refresh()`, so only the editor query is refreshed. The list's cached `findPlayers({ q, withProfile })` entries (`src/routes/+page.svelte`) survive navigation until garbage collection evicts them, and show stale badges.

Fix: drop the explicit refresh so the default `refreshAll()` runs. That refreshes `getEditor` and every cached `findPlayers` entry. `findPlayers` filters the server's cached fpa-api directory, so the refresh costs one profile-id query per cached list, not fpa-api reads.
