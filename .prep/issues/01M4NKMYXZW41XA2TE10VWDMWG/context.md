`saveProfile` in `src/lib/server/profiles.ts` upserts unconditionally. It receives fields already normalized by `normalizeFields` (`src/lib/profile/fields.ts`), which drops empty values, so "empty" is simply `Object.keys(fields).length === 0`. The change lives there, so every caller gets it: when empty, delete the row by `player_id`; otherwise upsert as before. Deleting a missing row is a no-op, which covers saving an empty form for a player without a profile.

The editor (`getEditor` in `src/routes/players/[playerId]/data.remote.ts`) already treats a missing row as "no profile" (`fields: {}`, `updatedAt: null`). The list's badge and filter come from `profiledPlayerIds()`, the export from `buildExport()`; both read the table, so both follow. See [Profile field registry and storage](/components/profile-fields.md).
